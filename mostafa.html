Three points most likely to cause rework

1 · Section 5

API name traps

Identical on-screen labels, different api_name by module.

Example: PO Line Number = cf_vendor_po_line_number on lines, but cf_po_line_number on SO header & Shipment.

Wrong name → HTTP success + value discarded. Verify in the organisation, not only response code.

2 · Serial

Serial tracking is OFF

TrackSerialNumber is false on all items. Only batch tracking is in use.

Old integration plan said serial + batch ON — correct that before treating the plan as final. Do not map serials.

3 · ASN

Locator per ASN line

STC locators vary line by line (2nd segment = line sequence). Header locator cannot represent a multi-line receipt.

ASN must carry locator per line. Batch reference depends on this.

4. Handbook — structured flow

Same story as the PDF, in reading order.

A. Warehouse

  • Parent location = container only
  • 6 child entities · each 18 zones
  • Integration writes stock only to RECEIVING bins
  • Shelf put-away = Move Order (manual, out of Phase 1)
  • Never use legacy Receiving Zone / Receiving Area

B. Inbound cycle

  1. AddPurchaseOrder → PO Issued (no stock)
  2. AddASN → Purchase Receive Pending Approval (no stock)
  3. Mezzan approves → stock to RECEIVING + batch created
  4. AddGRN fires to STC on approval

No separate ASN object in Zoho — ASN becomes a Purchase Receive. Do not auto-approve.

C. Outbound cycle

  1. AddSalesOrder / RFD → Sales Order (committed)
  2. Mezzan pick & pack → Package (batch selected)
  3. Mezzan ships → Shipment (stock leaves)
  4. SendShippingConfirmation on dispatch · cf_batch_id

Serial OFF. Expect many batches per item at picking.

D. Custom fields (why line-level)

  • PO / Line / Project / Release / Supplier Item Code at line
  • cf_supplier_s_item_code is mandatory
  • Locator on PR line = cf_storage_location (use this)
  • Dropdowns: 18 zones · Priority High/Med/Low · Ship With Care Yes/No

E. Batch formula (agreed with STC)

{Date Received dd/MM/yyyy} - {Full Locator} - {Supplier Item Code}

Spaced hyphens · from line locator · never shorten locator

F. Six Phase-1 APIs

  • Inbound: Item · PO · ASN · Sales Order
  • Outbound: AddGRN · SendShippingConfirmation
  • UAT: apitest.stcs.com.sa

5. Open decisions (Section 8) — for STC

Recommended positions so Waqqas can reply Mostafa and raise one request to STC.

D1

SO PO number fields

Both cf_po_number and cf_locator_po_number exist.

Recommend: STC poNumber → cf_po_number; keep locator PO separate.

D2

ASN locator per line

Required: Yes — must be in ASN payload for batch construction.

D3

Priority / Ship With Care

Expect High/Medium/Low and Yes/No — normalise if STC values differ slightly.

Verification checklist (from handbook)

  • Line-level CFs on every line
  • Supplier Item Code on every line
  • Sub-inventory = exact zone name
  • Stock only in RECEIVING bins
  • Batch formula exact (spaced) from line locator
  • Multi-line receipt with different locators tested
  • ASN pending · no stock until approval
  • GRN only on approval
  • Correct PO Line Number api_name per module
  • Partial receipt balances correct
  • Verify in org — not only HTTP 200
