2. Solution pattern (simple)

STC / TIBCO
   │  OAuth token + POST JSON
   ▼
Our webhook API  (Item / PO / ASN / SO)
   │  validate Bearer → map fields
   ▼
Zoho Inventory  (create / update records)

Mezzan works in Zoho (approve receive · pack · ship)
   │
   ▼
Zoho Flow HTTP  →  TIBCO AddGRN / SendShippingConfirmation

Inbound (STC → Zoho)

STC pushes Item, PO, ASN, Sales Order. We create Zoho records. Stock does not post on ASN — only after Mezzan approval.

Outbound (Zoho → STC)

AddGRN after Purchase Receive approved. SendShippingConfirmation after shipment shipped.

3. Build steps (follow in order)

  1. Lock STC answers — UAT api_key + Client-Id, webhook push yes, firewall allowlist, OAuth client credentials, Section 8 decisions (SO PO field, ASN line locator, Priority/Ship With Care enums).
  2. Create OAuth webhook layer — token URL + 4 POST endpoints. Validate Bearer. Return clear 401/400.
  3. Connect Zoho Inventory — server OAuth / connection with org id 150001417597. Write Items, POs, PRs, SOs with exact CF api_names.
  4. Inbound mapping — implement Item → PO → ASN(PR Pending) → SO using rules below. Locator per ASN line. Batch only on approval.
  5. Approval trigger — on Purchase Receive approved: post stock logic already in Zoho; Flow calls AddGRN.
  6. Outbound ship trigger — on Shipment shipped: Flow calls SendShippingConfirmation with cf_batch_id.
  7. Retries & alerts — 408/409 retry 3×; 400/401 no blind retry; email alert after failure.
  8. UAT — run checklist; verify values in Zoho UI, not only HTTP 200.

4. Inbound APIs (STC → our webhooks)

Payload shapes from DBSchenker v4.3. STC will POST equivalent JSON to our OAuth URLs. Spec paths below are the reference shapes / old STC URLs.

API 1 · AddItemRequest

Creates / updates Item in Zoho Inventory

INBOUND POST Spec path: /tibco/dbschenker/v1/supply-chain/item-master

Headers

  • api_key · Client-Id · Sender-Msg-Id (unique per call)
  • Our layer also requires Authorization: Bearer <access_token>

What we do in Zoho

  • SKU / item code = STC itemCode (searchable by name or SKU only)
  • Map supplierItemCode → cf_supplier_s_item_code (mandatory)
  • Batch tracking ON · Serial OFF — ignore serial mapping

Sample JSON (from STC spec)

  "batchId": "80",
  "batchDate": "2023-01-12T12:28:01",

API 3 · AddASN

Creates Purchase Receive in Pending Approval — no stock yet

INBOUND POST /tibco/erp/supply-chain/v1/asnasn

What we do in Zoho

  • Purchase Receive · status Pending Approval
  • Sub-Inventory mandatory · stock target later = RECEIVING bin only
  • Locator per line → cf_storage_location (required for batch)
  • Line refs: vendor line, STC item, supplier item, project, release
  • Do not auto-approve

Note

v4.3 sample may omit line locator — Mostafa/handbook require STC to send it. Confirm in Section 8 / STC new API doc.

API 4 · AddSalesOrder / CreateRFD

Creates Sales Order — stock committed, not shipped

INBOUND POST /tibco/dbschenker/v1/supply-chain/sales-order

What we do in Zoho

  • Header: rfdNumber, dates, customer, project, waybill
  • transactionPriority → dropdown High/Medium/Low (normalise case)
  • shipWithCare → Yes/No
  • Map STC poNumber → cf_po_number (keep cf_locator_po_number separate)
  • Lines: item, qty, subInventory, poLineNumber → use correct CF api_name

6. Zoho mapping rules (do not skip)

Always

  • Org ID on every Zoho API call: 150001417597
  • cf_supplier_s_item_code on every line
  • Stock only to {City} - {SubInv} - RECEIVING
  • Batch: {dd/MM/yyyy} - {Locator} - {SupplierItemCode}
  • Verify CF values in Zoho UI after write

API name traps

  • Lines: cf_vendor_po_line_number
  • SO header / Shipment: cf_po_line_number
  • PR line locator: cf_storage_location
  • Wrong name = HTTP 200 + empty field
Out of Phase 1: POD, Move Order API, Returns/RTV, stock snapshot, PO update/cancel beyond create.

7. Error handling

HTTPMeaningOur action
200 / 201 (+ business success flag)OKLog · no retry
400ValidationAlert · fix payload · no blind retry
401AuthAlert · check api_key / Client-Id / Bearer
404URLAlert · verify endpoint
408 / 409Timeout / backendRetry up to 3× then alert

batchId must be unique. Duplicate batchId returns error.

8. UAT checklist

  • Item create + update
  • Multi-line PO · STC PO number preserved · Issued
  • ASN → PR Pending · no stock · locator on each line
  • Approve PR → stock in RECEIVING · batch formula correct · AddGRN 200/201
  • SO / RFD with Priority + Ship With Care + PO CFs
  • Ship → SendShippingConfirmation success · cf_batch_id set
  • 400 and 408/409 behaviour verified
  • All CF values visible in Zoho org (not only HTTP success)
